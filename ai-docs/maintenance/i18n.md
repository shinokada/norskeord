# i18n check scripts

Five scripts keep `messages/*.json` (nb/en/es/uk/de) honest. Each checks a
different thing — run the one that matches what you just changed.

| Script | Checks | Alias | Destructive |
|---|---|---|---|
| `check-message-keys.mjs` | Every locale has the same key set as `en.json` | `pnpm check:i18n` (part of) | No |
| `check-category-keys.ts` | Every `CATEGORIES_BY_LEVEL` slug has a matching `category_<level>_<slug>` key | `pnpm check:i18n` (part of) | No |
| `check-unused-keys.mjs` | Which `en.json` keys have no static/dynamic reference in `src/`; writes a report to `scripts/outputs/` | `pnpm check:i18n` (part of) / `pnpm check:unused-keys` | No (report only) |
| `check-language-sync.mjs` | The supported-language *set* is consistent across `config.ts`, inlang settings, paraglide runtime, server validation, DB migrations | `pnpm check:languages` | No |
| `remove-unused-keys.mjs` | Deletes the "unused" bucket from the latest `check-unused-keys.mjs` report, from every locale file | none | **Yes** — dry-run by default, needs `--apply` + confirmation |

`check-category-keys.ts` matters even though `check-unused-keys.mjs` also
looks at `category_*` keys: `check-unused-keys` only detects that the whole
`category_*` family is dynamically indexed (via `categoryLabel()`'s `m[key]`
pattern) and treats all of it as "used" — it can't catch one specific
missing key like `category_c_gastronomy`. Only `check-category-keys.ts`
cross-references `CATEGORIES_BY_LEVEL` key-by-key against `en.json`.

## Routine check

After touching `messages/*.json` or `CATEGORIES_BY_LEVEL` in `config.ts`:

```bash
pnpm check:i18n   # check-message-keys.mjs && check-unused-keys.mjs && check-category-keys.ts
```

Fix anything it flags before opening a PR.

## Adding or removing a supported language

```bash
pnpm check:languages
```

Follow its printed instructions until it passes, then also run
`pnpm check:i18n` — a new locale needs a `messages/{code}.json` with full
key parity too.

## Cleaning up unused keys (the only destructive workflow)

1. `node scripts/check-unused-keys.mjs` — read the "unused" bucket in the
   terminal output, or the full report in
   `scripts/outputs/unused-keys-*.json`. This is the manual review step —
   don't skip it.
2. `node scripts/remove-unused-keys.mjs` — dry run, confirms the plan.
3. `node scripts/remove-unused-keys.mjs --apply` — asks y/N, then writes.
4. `pnpm check:i18n` — confirms all locales still match after the deletion.

`remove-unused-keys.mjs` always trusts the *most recent* report and never
re-derives "unused" itself — run step 1 immediately before steps 2–3, not
against a stale report from an earlier session.

Don't wire `remove-unused-keys.mjs --apply` into CI — it deletes from all 5
locale files at once and needs a human to have actually read the list first.
